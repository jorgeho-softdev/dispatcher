# Internacionalización (i18n)

En Canadá, buena parte de los transportistas son migrantes. AI Dispatcher está pensado para varios idiomas desde la base: **web, app y API comparten la misma lista de idiomas y los mismos catálogos de traducción.**

## Idiomas soportados

| Código | Idioma | Formato (Intl) | Estado |
|---|---|---|---|
| `en` | English | `en-CA` | ✅ revisado (catálogo fuente) |
| `fr` | Français | `fr-CA` | ⚠️ **needs_review** (requiere revisión nativa) |
| `es` | Español | `es-419` | ✅ revisado |
| `pa` | ਪੰਜਾਬੀ (punjabi, gurmukhi) | `pa-Guru-IN` | ⚠️ **needs_review** (requiere revisión nativa) |

> ⚠️ **Antes del lanzamiento**, un hablante nativo debe revisar las traducciones de francés y punjabi y marcarlas como `reviewed` en `packages/i18n/src/locales.ts`. Fueron redactadas sin revisión nativa.

**Candidatos siguientes** por población migrante en transporte canadiense: tagalo (`tl`), hindi (`hi`), chino (`zh-Hans`/`zh-Hant`), vietnamita (`vi`), ucraniano (`uk`), árabe (`ar`, RTL) y urdu (`ur`, RTL). Validarlo con los usuarios.

## Arquitectura

```
packages/i18n
├── src/locales.ts        LOCALES, LOCALE_INFO (nombre nativo, dir ltr/rtl, intlLocale, estado),
│                         negotiateLocale(), parseAcceptLanguage()
├── src/index.ts          MESSAGES, getMessages(), tipo Messages (= en.json)
└── messages/<locale>.json  Catálogos ICU: common · domain · errors · auth · web · mobile
```

| Capa | Cómo usa i18n |
|---|---|
| **API** | No traduce texto para el usuario. Devuelve **códigos de error estables** (`ApiErrorDto.code`, lista en `ERROR_CODES` de `@dispatcher/shared`) y guarda el idioma preferido del usuario (`users.locale`, `PATCH /v1/me`), que usarán las notificaciones push y los correos en fases futuras. |
| **Web** | **next-intl**. Las URLs llevan el idioma (`/pa/loads`) y cada página se prerenderiza por idioma. `proxy.ts` negocia el idioma (cookie `NEXT_LOCALE` → `Accept-Language` → `en`). `<html lang dir>` es dinámico. El selector de idioma está en el login y en la barra superior; si hay sesión, también guarda el idioma en el perfil. |
| **Mobile** | **use-intl** (el núcleo de next-intl), con los mismos catálogos. El primer arranque usa el idioma del dispositivo (`pa-IN` → `pa`) y el usuario puede cambiarlo en Ajustes. Un listener de Redux sincroniza el idioma con el perfil. |

### Reglas (obligatorias)

1. **Ningún texto visible escrito a mano** en web ni en mobile: todo pasa por `t()`.
2. **Mensajes en formato ICU.** Variables `{name}`, plurales `{count, plural, one {…} other {…}}`. **Nunca** concatenes frases: el orden de las palabras cambia entre idiomas.
3. **Formatos según el idioma:**
   - Fechas y números: `useFormatter()` (o `format.dateTime` / `format.number`).
   - Dinero: `formatMoney(amount, currency, intlLocale)`.
   - El `intlLocale` sale de `useIntlLocale()`.
4. **Los errores de la API se traducen por código:** `t(\`errors.${code}\`)`. Nunca muestres `message` de la API al usuario.
5. **Los enums del dominio se traducen** con `domain.equipment.<tipo>` y `domain.role.<rol>`.
6. **Nada de banderas para idiomas** (un idioma no es un país). Los selectores muestran el nombre nativo (`ਪੰਜਾਬੀ`, `Français`).
7. **RTL:** en web usa propiedades lógicas de Tailwind (`ms-*`, `me-*`, `text-start`, `text-end`, `border-e`) en lugar de `ml/mr/left/right`. Así árabe o urdu funcionarán sin rediseñar.

## Cómo agregar una clave
Sigue el skill `apps/mobile/.claude/skills/add-i18n-key/SKILL.md` (sirve para ambas apps):
1. Agrégala en `messages/en.json` y en **todos** los demás catálogos, en la misma ruta.
2. `npm run build --workspace=@dispatcher/i18n && npm test --workspace=@dispatcher/i18n`. El test falla si falta una clave o si las `{variables}` no coinciden con las de inglés.

## Cómo agregar un idioma nuevo (p. ej. tagalo)

1. Agrega `'tl'` a `LOCALES` y su entrada en `LOCALE_INFO` (`nativeName: 'Tagalog'`, `dir`, `intlLocale: 'fil-PH'`, `status: 'needs_review'`).
2. Copia `messages/en.json` a `messages/tl.json`, tradúcelo y regístralo en `MESSAGES` (`src/index.ts`).
3. Corre `npm run build --workspace=@dispatcher/i18n && npm test --workspace=@dispatcher/i18n`.
4. Listo: la web genera `/tl/...`, el selector lo muestra y la API lo acepta en `PATCH /v1/me`.
5. **Si es RTL** (árabe, urdu, farsi):
   - **Web:** funciona automáticamente con `dir="rtl"`.
   - **Mobile:** hay que llamar a `I18nManager.forceRTL()` y recargar la app al cambiar de dirección. Implementarlo junto con el primer idioma RTL.
